 场景 A：CPU 跑到 target_va 执行（正常调用）

  CPU PC=0x7000, 需要取指
     │                                                                                        
     ▼
  PTE.protected_pte (PFN_SHADOW, EL0=--x)                                                     
     │  exec 权限 OK                                              
     ▼                                                                                        
  取出 trampoline 字节  →  跳到 frida hook stub  ✓
                                                                                              
  场景 B：别的页里的代码 LDR 读 target_va（外部反作弊读）                                     
   
  CPU PC=0x9000 (其它页), LDR x0,[0x7000]                                                     
     │                                                                                        
     ▼
  PTE.protected_pte (--x), 没有 r 权限                                                        
     │                                                            
     ▼  permission abort, 落 do_page_fault
     ▼
  text_shadow.do_page_fault_before:
     - is_read_perm_fault: true
     - PC(0x9000) ≠ pp->page_start(0x7000)
     - 走 path A: *ptep = alt_pte; tlbi
     - skip_origin = 1
     ▼
  CPU retry LDR
     │
     ▼
  PTE.alt_pte (PFN_ALT, EL0=r--)
     │
     ▼
  读到纯净字节  ✓ (反作弊看到原始代码)
     │
     ▼  之后 CPU 想再去 0x7000 执行
     ▼
  PTE.alt_pte (UXN=1, 无 exec) → instruction abort
     ▼
  text_shadow.do_page_fault_before:
     - is_instruction_abort: true
     - 切回 *ptep = protected_pte; tlbi
     ▼
  CPU retry IFETCH → 走 trampoline  ✓

  场景 C：trampoline 自己读自己（同页，path B emulate）

  trampoline 在 0x7000 处, 第一条 ldr x16,[pc,#8] 要读 0x7008
  PC=0x7000 (在保护页内), 读 0x7008 (也在保护页内)
     │                                                                                        
     ▼
  PTE.protected_pte (--x), 不能读 → 落 do_page_fault                                          
     │                                                            
     ▼
  text_shadow.do_page_fault_before:
     - PC 页 == 保护页
     - PC 在 frida_entry_pcs 白名单里 (是 trampoline 入口) → is_tramp=1
     - src_kva = pa_to_kva(saved_pte.PFN) = SHADOW 的 kva (含 trampoline)
     - emulate_load: 解码这条 ldr, 直接从 shadow_kva+offset 读字节, 写进 regs->Rt
     - PC += 4                                                                                
     - 不动 PTE !                                                                             
     ▼                                                                                        
  CPU 看到这条 ldr 已"完成", 继续下一条                                                       
                                                                                              
  为什么同页不能切 PTE？切到 alt 之后 IFETCH 立刻 abort，切回 shadow 之后 LDR 又              
  abort，死循环。所以同页只能在 fault handler 里软件模拟那一条 load。                         
                                                                                              
  场景 D：/proc/self/mem 读、process_vm_readv、ptrace peek                                    
  
  这些走 access_remote_vm → GUP, 不经 do_page_fault                                           
     │                                                                                        
     ▼
  text_shadow.access_remote_vm_before (前置 hook):                                            
     - 命中范围 → *ptep = alt_pte                                                             
     ▼                                                                                        
  GUP 拿到 alt 的 page → 拷贝纯净字节给读者 ✓                                                 
     ▼                                                                                        
  text_shadow.access_remote_vm_after (后置 hook):                 
     - *ptep = protected_pte

  二、当前问题（你之前提的脏段 / pageinfo）                       
                                                                                              
  SO 原本一段 VMA:
    7000-7fff  r-xp  /system/lib64/libtarget.so                                               
                                                                                              
  frida mprotect(rwx) 单页 → 写 → mprotect(rx):                                               
    6000-6fff  r-xp  /system/lib64/libtarget.so   ← VMA1                                      
    7000-7fff  r-xp  /system/lib64/libtarget.so   ← VMA2 (被切出来的)                         
    8000-8fff  r-xp  /system/lib64/libtarget.so   ← VMA3                                      
                  ↑                                                                           
             物理 PFN 已 CoW 成 anon, 跟 VMA1/3 不同                                          
             pagemap 看 VMA2 那页 PFN ≠ libtarget.so pagecache PFN                            
             → 即使 wxshadow 接管, 这两件事都已成事实:                                        
               1. /proc/maps 三段                                                             
               2. /proc/self/pagemap PFN 偏移                                                 
                                                                                              
  wxshadow 接手时机太晚，VMA 已经撕了，PFN 已经偏了。

  三、stealth 设计：让 frida 别去碰 SO 的 VMA                     
                                                                                              
  核心想法
                                                                                              
  frida 不在 SO .text 页上写任何东西。 trampoline 字节预备到一块自己 mmap 出来的独立 anon     
  页（fake_page），然后让 KPM 把目标 SO 那页的 PTE 直接改指向 fake_page 的 PFN。              
                                                                                              
  SO 的 VMA 全程 r-xp 不变 → maps 不撕。SO 的 .text 页根本没被写过 → 不发生 CoW，原始 PFN     
  不变。
                                                                                              
  物理页布局（stealth 模式）                                      

  进程虚拟空间                     物理页
  ──────────────                   ─────                                                      
  [libtarget.so .text VMA - 完整 r-xp 一段, 始终不动]
  target_va: 0x7000  PTE ──→ PFN_SO_PAGECACHE  (修改前)                                       
                                                                                              
  [frida 自己 mmap 出来的 anon VMA]                                                           
  fake_va:   0xA000  PTE ──→ PFN_FAKE                                                         
                              ↑ frida 自己往这页写:                                           
                                [原 4096 字节] + [trampoline 覆盖]                            
                                然后 mprotect 回 r-x                                          
                                                                                              
  [KPM 私有]                  PFN_ALT                                                         
                              ↑ KPM 分配, 装 [纯净原 4096 字节]                               
                                                                                              
  切换之后                                                        
                                                                                              
  target_va: 0x7000  PTE ──→ PFN_FAKE  EL0=--x   (新 protected_pte)
                                  ↑                                                           
                                  现在 SO .text VMA 第一页 PTE 指向了 fake!
                                  但 VMA 元数据没动, 还是 r-xp + 文件背景                     
                                  /proc/maps 看不到任何变化                                   
                                                                                              
  target_va: 0x7000  PTE ──→ PFN_ALT   EL0=r--   (alt_pte, 切换时启用)                        
                                                                  
  saved_pte: PFN_SO_PAGECACHE                    (卸载时用来还原)                             
                                                                  
  数据流（与现行的差别）                                                                      
                                                                  
  四个场景的 fault handling 流程完全不变，只是 PFN 来源换了：                                 
                                                                  
  ┌──────────┬──────────────────────┬───────────────────────────┐                             
  │   场景   │    wxshadow 现行     │          stealth          │ 
  ├──────────┼──────────────────────┼───────────────────────────┤
  │ A 执行   │ shadow=CoW 出的 anon │ shadow=frida mmap 的 fake │
  ├──────────┼──────────────────────┼───────────────────────────┤
  │ B 外读   │ 切 alt（KPM 分配）   │ 同                        │                             
  ├──────────┼──────────────────────┼───────────────────────────┤                             
  │ C 自读   │ emulate 从 shadow 读 │ emulate 从 fake 读        │                             
  ├──────────┼──────────────────────┼───────────────────────────┤                             
  │ D mem 读 │ 切 alt               │ 同                        │ 
  └──────────┴──────────────────────┴───────────────────────────┘                             
   
  所有 path B 的指令模拟、path A 的 PTE 切换逻辑都不用动。改动仅在"shadow 这个 PFN 来源"。    
                                                                  
  KPM 需要的最小变更                                                                          
                                                                  
  现 prctl 接口：                                                                             
  prctl(PROTECT, target_va, clean_buf, 0, 0)                      
     → 内核读 *ptep 拿 PFN 当 shadow        
                                                                                              
  新增第 4 参数 = fake_va（frida 自己 mmap 的那页用户 VA）：                                  
  prctl(PROTECT, target_va, clean_buf, fake_va, 0)                                            
     → 内核 walk fake_va 的 PTE 拿 PFN_FAKE                                                   
     → saved_pte    = *target_ptep                                (PFN_SO_PAGECACHE)          
     → protected_pte= (fake_pte & ~USER & ~UXN) | exec_only        (PFN_FAKE)                 
     → alt_pte      = build alt with clean_buf, EL0 r--            (PFN_ALT)                  
     → *target_ptep = protected_pte                                                           
     → tlbi target_va                                                                         
                                                                                              
  frida 整个生命周期完全没调过 SO 上的 mprotect。                                             
                                                                                              
  卸载                                                            
                                                                                              
  prctl(UNPROTECT, target_va):                                    
     *target_ptep = saved_pte    (PFN_SO_PAGECACHE)                                           
     释放 PFN_ALT
                                                                                              
  frida 自己 munmap 掉 fake VMA，干干净净。                                                   
   
  maps / pagemap 静态对比                                                                     
                                                                  
                           clean 进程     现 wxshadow      stealth                            
  ─────────────────────────────────────────────────────────────────                           
  /proc/self/maps SO 段     1 段 r-xp     3 段 r-xp        1 段 r-xp ✓                        
  SO 那页 pagemap.PFN      SO_PAGECACHE  ANON_COW         ?                                   
                                                                                              
  stealth 下那一栏取决于 PTE 当前指的页：                                                     
    protected_pte 状态 → PFN_FAKE      (anon, 跟 SO 不一样, pagemap 仍可看出)                 
    alt_pte 状态       → PFN_ALT       (anon, 也不一样)                                       
                                                                  
  stealth 解决了 maps 撕裂，但 pagemap 上 SO 那页 PFN 跟纯净进程仍不一致。要把 pagemap        
  也对齐，得让 alt_pte 复用 SO 文件 pagecache 的 PFN（即 alt 不是新分配，而是
  find_get_page(file->f_mapping, pgoff) 拿到的那一页），并且在用户来"读 self                  
  pagemap"的瞬间确保 PTE 在 alt 状态。这个是后续优化，第一阶段先不做。
